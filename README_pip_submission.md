# Cravr

Cravr is a Django-based restaurant discovery and review web application. Users can browse and filter restaurants, view restaurants on a map, save restaurants to a wishlist, submit restaurants for approval, write reviews with photo attachments, and manage user profiles.

This README is written for the **submitted ZIP version** of the project. The evaluator does **not** need to clone the project from GitHub and does **not** need to install `uv`.

The standard execution method uses **Python + pip**.

---

---

# 6. Security Note About `.env`

The `.env` file is included in the private academic submission so that the evaluator can run the application without recreating the external-service configuration.

Anyone who receives the ZIP can read the values inside `.env`.

For this reason:

- `.env` should not be uploaded to a public GitHub repository.
- Personal account passwords should never be stored in `.env`.
- Submission/demo credentials should be used where possible.
- Shared credentials should be rotated or revoked after the assessment period if necessary.

# 7. Database

Cravr uses SQLite.

The local/submission database is stored at:

```text
data/db.sqlite3
```

The Django configuration uses:

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "data" / "db.sqlite3",
    }
}
```

The submitted ZIP may already contain the database with sample/demo data.

Running:

```bash
python manage.py migrate
```

is safe. If the database is already up to date, Django will report that no migrations need to be applied.

# 12. Google Sign-In

Cravr uses `django-allauth` for Google authentication.

The Google Sign-In credentials are:

```env
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
```

These credentials are separate from the Gmail API credentials.

The local OAuth callback URL is:

```text
http://127.0.0.1:8000/accounts/google/login/callback/
```

If `localhost` is used instead of `127.0.0.1`, this callback may also be configured:

```text
http://localhost:8000/accounts/google/login/callback/
```

---

# 13. Google Account Linking

Cravr uses:

```text
accounts/adapter.py
```

with a custom `CustomSocialAccountAdapter`.

If a Google account signs in with an email address that already belongs to an existing Cravr user, the Google account can be connected to that existing account.

Relevant configuration includes:

```python
SOCIALACCOUNT_ADAPTER = 'accounts.adapter.CustomSocialAccountAdapter'
LOGIN_REDIRECT_URL = '/accounts/google-login-redirect/'
SOCIALACCOUNT_EMAIL_AUTHENTICATION = False
SOCIALACCOUNT_EMAIL_AUTHENTICATION_AUTO_CONNECT = True
```

New Google users are redirected through the project's Google-login redirect flow so they can complete password setup instead of becoming stuck after OAuth login.

---

# 14. Gmail API and OTP Verification

Cravr uses the Gmail API to send OTP verification and other account-related emails.

The Gmail API configuration uses:

```env
GMAIL_CLIENT_ID=...
GMAIL_CLIENT_SECRET=...
GMAIL_REFRESH_TOKEN=...
GMAIL_SENDER_EMAIL=...
```

These are different from:

```env
GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
```

which are used for Google Sign-In.

---

# 15. Registration Flow

Normal registration follows this process:

```text
Register
   ↓
User account created
   ↓
OTP generated
   ↓
OTP sent through Gmail API
   ↓
User enters OTP
   ↓
Account marked as verified
   ↓
User can log in
```

The application uses its Gmail API helper to send the OTP.

# 18. Existing User Without a Profile

Cravr expects users to have a related `Profile`.

If an account produces:

```text
RelatedObjectDoesNotExist
User has no profile.
```

run:

```bash
python manage.py shell
```

Then:

```python
from django.contrib.auth.models import User
from accounts.models import Profile

user = User.objects.get(username="YOUR_USERNAME")
Profile.objects.get_or_create(user=user)
```

Exit:

```python
exit()
```

# 22. Troubleshooting

## `python` is not recognized

Try:

```bash
python3 --version
```

If Python is not installed, Python itself is the only runtime prerequisite required for the standard submission setup.

---

## Dependency installation fails

Make sure the terminal is inside the project root containing:

```text
requirements.txt
pyproject.toml
manage.py
```

Then run:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The supplied `requirements.txt` contains an editable local-project entry (`-e .`), so running it from another directory may fail.

---

## `Error 401: invalid_client`

Check the Google Sign-In values in `.env`:

```env
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
```

These must belong to the Google OAuth client used for Sign in with Google.

They must not be replaced with the Gmail API credential pair.

---

## `redirect_uri_mismatch`

The Google OAuth configuration must include the local callback:

```text
http://127.0.0.1:8000/accounts/google/login/callback/
```

---

## OTP signup returns HTTP 500

Check that `.env` contains:

```text
GMAIL_CLIENT_ID
GMAIL_CLIENT_SECRET
GMAIL_REFRESH_TOKEN
GMAIL_SENDER_EMAIL
```

Also confirm that the registration and resend flows use the Gmail API OTP helper.

---

## `User has no profile`

Create the missing profile with:

```python
from django.contrib.auth.models import User
from accounts.models import Profile

user = User.objects.get(username="YOUR_USERNAME")
Profile.objects.get_or_create(user=user)
```

---

## Uploaded media does not appear

Check that:

```text
data/media/
```

exists and that the required uploaded assets are present in the extracted ZIP.

---

## Seed CSV is missing

Check:

```text
seed_data/restaurants.csv
```

The seed CSV should not be expected at:

```text
data/restaurants.csv
```

# 24. Preparing the Submission ZIP

The final submission must remain below **100 MB**.

## Include

```text
accounts/
restaurants/
cravr_project/
templates/
static/
seed_data/
data/db.sqlite3       # if required for demo/sample data
data/media/           # if required for demo/sample media
manage.py
requirements.txt
pyproject.toml
uv.lock
.env
README.md
```

## Exclude

```text
.venv/
.git/
__pycache__/
*.pyc
staticfiles/
```

Reasons:

- `.venv/` is large and machine-specific.
- `.git/` is not required to run the submitted program.
- `__pycache__/` and `*.pyc` are generated automatically.
- `staticfiles/` is generated output and can be recreated if needed.

Do **not** include the virtual environment just to avoid dependency installation. A virtual environment copied from one computer may not work correctly on another computer and can easily push the ZIP over the 100 MB limit.
